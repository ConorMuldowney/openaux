# Linear CSV Format Specification

## Overview

This document defines the canonical CSV standard for OpenAux tickets generated for Linear import. It also describes how those fields appear in Linear CSV exports so one format can be used consistently in both directions.

## Column Definitions

| Column | Type | Required | Description |
|--------|------|----------|-------------|
| **ID** | string | No (import) / Yes (export) | Linear ticket identifier (e.g., `AUX-5`). Leave blank when importing new tickets; Linear auto-generates it. Present in exports. |
| **Team** | string | Yes | Team name (e.g., `OpenAux`). Must match an existing team in the Linear workspace. |
| **Title** | string | Yes | Ticket title/headline. Should be concise and descriptive. |
| **Description** | string | No | Full ticket description in markdown. Can include acceptance criteria (AC:), dependencies, and detailed requirements. |
| **Status** | enum | Yes | Workflow state: `Backlog`, `Todo`, `In Progress`, `In Review`, `Done`, `Canceled`. |
| **Estimate** | number | No | Story points (e.g., `3`, `5`, `8`). Leave blank for unestimated tickets. |
| **Priority** | enum | No | Priority level: `High`, `Medium`, `Low`. Defaults to `Medium` if omitted. |
| **Project ID** | string | No | Linear project identifier. Usually empty in OpenAux usage. |
| **Project** | string | No | Project name. Usually empty in OpenAux usage. |
| **Creator** | email | Yes | Email address of ticket creator (e.g., `conormuldowney6@gmail.com`). |
| **Assignee** | email | No | Email address of assigned owner. Leave blank for unassigned. |
| **Labels** | string | No | Comma-separated list of label names (e.g., `lifecycle`, `platform`, `testing`). Tags for categorization. |
| **Cycle Number** | number | No | Sprint/cycle number. Usually blank. |
| **Cycle Name** | string | No | Sprint/cycle name. Usually blank. |
| **Cycle Start** | datetime | No | Cycle start date. Usually blank. |
| **Cycle End** | datetime | No | Cycle end date. Usually blank. |
| **Created** | datetime | No (import) / Yes (export) | Ticket creation timestamp. Format in exports: `Tue Jun 09 2026 14:59:36 GMT+0000 (GMT+00:00)`. Auto-populated by Linear. |
| **Updated** | datetime | No (import) / Yes (export) | Last update timestamp. Auto-populated by Linear. |
| **Started** | datetime | No | Timestamp when ticket moved to `In Progress`. Auto-tracked by Linear. |
| **Triaged** | datetime | No | Timestamp when ticket was triaged. Auto-tracked by Linear. |
| **Completed** | datetime | No | Timestamp when ticket moved to `Done`. Auto-tracked by Linear. |
| **Canceled** | datetime | No | Timestamp when ticket was canceled. Auto-tracked by Linear. |
| **Archived** | datetime | No | Timestamp when ticket was archived. Auto-tracked by Linear. |
| **Due Date** | date | No | Optional due date. Format: `YYYY-MM-DD` or similar. |
| **Parent issue** | string | No | Reference to parent ticket ID (e.g., `AUX-5`). Links to epic or parent story. |
| **Initiatives** | string | No | Comma-separated list of initiative references (e.g., `AUX-41, AUX-43`). |
| **Project Milestone ID** | string | No | Linear project milestone identifier. Usually blank. |
| **Project Milestone** | string | No | Project milestone name. Usually blank. |
| **SLA Status** | string | No | Service level agreement status. Usually blank. |
| **UUID** | string | No (import) / Yes (export) | Unique identifier generated by Linear. Auto-populated by Linear. |
| **Time in status (minutes)** | number | No | Time spent in current status. Auto-calculated by Linear. |
| **Related to** | string | No | Comma-separated list of related ticket IDs (e.g., `AUX-41, AUX-43`). Bidirectional relationships. |
| **Blocked by** | string | No | Comma-separated list of ticket IDs that block this ticket. |
| **Duplicate of** | string | No | Reference to duplicate ticket ID if this is a duplicate. |

## Data Types & Formats

### Status Values
- `Backlog` - Unstarted work
- `Todo` - Ready to start
- `In Progress` - Currently being worked on
- `In Review` - Awaiting review
- `Done` - Completed work
- `Canceled` - Canceled/abandoned work

### Priority Values
- `High` - Critical path, blocking items
- `Medium` - Standard priority (default)
- `Low` - Nice-to-have, backlog items



### Datetime Format
Linear export timestamps commonly use the following UTC/GMT string format:
```
Tue Jun 09 2026 14:59:36 GMT+0000 (GMT+00:00)
```

For new-ticket imports, prefer leaving Linear-managed datetime fields blank (`Created`, `Updated`, `Started`, `Triaged`, `Completed`, `Canceled`, `Archived`) so Linear populates them.

### Email Format
- Must be valid email addresses: `user@domain.com`
- Creator field is required; assignee is optional

### Labels
- Comma-separated, no extra spaces
- Examples: `lifecycle`, `platform`, `testing`, `access`, `submission`, `ballots`, `visibility`, `host-controls`, `frontend`
- Common labels in OpenAux:
  - **Domain area**: `lifecycle`, `policy`, `submissions`, `ballots`, `scoring`, `visibility`
  - **Type**: `testing`, `platform`, `frontend`
  - **Feature**: `access`, `host-controls`

### Relationships (Related to, Blocked by, Duplicate of, Initiatives, Parent issue)
- Single ticket: `AUX-41`
- Multiple tickets: `AUX-41, AUX-43` (comma-separated with space)
- Leave blank if not applicable

## Importing Tickets via Linear CLI

When preparing a CSV for import:

1. **Ensure ID column is empty or omitted** - Linear will auto-generate IDs
2. **Prefer blank Linear-managed timestamps** - If provided, use the export-style GMT/UTC format shown above
3. **Validate email addresses** - Creator must be valid, assignee optional
4. **Use consistent delimiters** - Commas for multi-value fields like labels and relationships
5. **Preserve quote escaping** - Text containing commas should be quoted
6. **Team name must match** - Must correspond to existing Linear team

### Required Fields for New Import
- Team
- Title
- Creator (email)
- Status

### Auto-Generated Fields
- ID
- UUID
- Created
- Updated

## Notes

- **CSV Format**: UTF-8 encoding, standard comma-separated with quoted fields
- **Datetime Handling**: All dates are in GMT/UTC. Local time is displayed in the UI
- **Deleted Tickets**: Archiving is preferred over deletion for audit trail
- **Relationships**: Always use the full ticket ID format (e.g., `AUX-41`)
- **Large Descriptions**: Markdown is fully supported in the Description field, including code blocks
